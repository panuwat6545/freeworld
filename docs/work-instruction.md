## 1. หลักการทำงาน (ห้ามฝ่าฝืน)

1. **ห้ามข้ามเฟส** — ต้องทำตามลำดับเฟสในข้อ 3 เท่านั้น ห้ามเริ่มเฟสถัดไปก่อนเฟสก่อนหน้าผ่านเกณฑ์ Definition of Done (ข้อ 4)

3. **ทุก session ต้อง commit เป็นรอบเล็กๆ** พร้อมข้อความ commit ตามรูปแบบข้อ 5.2 ห้าม commit รวบยอดหลายฟีเจอร์ในครั้งเดียว
4. **ห้ามเขียน API key, credential, หรือ secret ลงในโค้ดหรือ commit ใดๆ** ให้อ่านผ่าน environment variable เท่านั้น (ดูข้อ 6)
5. **ก่อนปิดงานทุกเฟส ต้องอัปเดตส่วน "Changelog" ท้ายไฟล์นี้**

## 2. การแบ่งหน้าที่เครื่องมือ: Plugin / Skill / Tool

เพื่อไม่ให้ทำงานปนกันจนผิดเพี้ยน ให้ยึดหลักนี้ในการเลือกใช้:

| ประเภท | คืออะไร | ใช้เมื่อไหร่ | ตัวอย่างในโปรเจกต์นี้ |
|---|---|---|---|
| **Tool** | คำสั่งพื้นฐานที่เรียกตรง (bash, แก้ไฟล์, git, อ่าน/เขียนไฟล์) | งานทั่วไปทุกประเภท ใช้เป็นค่าเริ่มต้นเสมอ | สร้างไฟล์ `.js`, รัน `npm install`, `git commit` |
| **Skill** | ชุดคำแนะนำ/มาตรฐานสำเร็จรูปสำหรับงานเฉพาะด้าน ที่ทำให้ผลลัพธ์สม่ำเสมอทุกครั้ง | เมื่องานนั้นมีมาตรฐานที่ต้องทำซ้ำๆ และมีความเสี่ยงถ้าทำไม่ตรงแบบ | รีวิวโค้ดก่อน merge, ออกแบบ test strategy, เขียนเอกสาร README |
| **Plugin** | ชุดรวม skill + tool + command สำหรับทั้งโดเมน ติดตั้งเพิ่มเมื่อโปรเจกต์ต้องใช้ความสามารถเฉพาะทางต่อเนื่อง | เมื่อมีงานเฉพาะทางเกิดขึ้นซ้ำตลอดโปรเจกต์ (ไม่ใช่ครั้งเดียวจบ) | งาน data pipeline, งาน dashboard, งานที่ต้องเชื่อมบริการภายนอกซ้ำๆ |

**กฎการเลือก:** เริ่มจาก Tool เสมอ ถ้างานมีความเสี่ยงสูง (โครงสร้างระบบ, ตรรกะ AI ของตัวละคร, ความปลอดภัยของ credential) ให้ค้นหา Skill ที่เกี่ยวข้องก่อนลงมือ (เช่น `engineering:code-review`, `engineering:architecture`, `engineering:testing-strategy`) อย่าลงมือเขียนเองตามความรู้สึกถ้ามี Skill ที่ตรงงานอยู่แล้ว

## 3. ลำดับเฟสการพัฒนา

### เฟส 1 — โลกและทรัพยากร
- Grid โลกขนาด 40x40, ทรัพยากรธรรมชาติ (ไม้/น้ำ/แร่/อาหาร) งอกใหม่ตามเวลา
- ยังไม่มีตัวละครหรือ AI

### เฟส 2 — ตัวละครและระบบความคิด (Utility AI)
- ตัวละครมีค่าความต้องการ (หิว/พลังงาน/ที่อยู่/สังคม)
- ระบบเลือกพฤติกรรมตามความต้องการที่วิกฤตที่สุดโดยอัตโนมัติ (ไม่ใช้ LLM ต่อตัวละคร)

### เฟส 3 — ระบบสร้างสิ่งของ (Building/Crafting)
- ตัวละครเก็บทรัพยากรครบตามสูตร (blueprint) แล้วสร้างสิ่งก่อสร้างได้เอง

### เฟส 4 — ระบบสังคม/การขยายเผ่าพันธุ์ (ถ้าต้องการ)
- ปฏิสัมพันธ์ระหว่างตัวละคร, การขยายจำนวนประชากรในเกม

### เฟส 5 — บันทึกข้อมูลลง Google Drive
- บันทึกสถานะโลกเป็นไฟล์ JSON ตามรอบเวลาที่กำหนด (ดูข้อ 6)

## 4. Definition of Done ของแต่ละเฟส

เฟสจะถือว่า "เสร็จ" ก็ต่อเมื่อครบทุกข้อนี้:

- [ ] โค้ดรันได้จริงไม่มี error ใน console
- [ ] มีคำอธิบายสั้นๆ ในไฟล์ `README.md` ว่าเฟสนี้ทำอะไร ทดสอบยังไง
- [ ] ไม่มี credential หรือ API key หลงเหลือในโค้ด
- [ ] Commit แล้วขึ้น branch `main` (หรือ branch ย่อยที่ merge แล้ว)
- [ ] อัปเดต Changelog ท้ายไฟล์นี้

## 5. มาตรฐานโค้ดและโครงสร้างไฟล์

### 5.1 โครงสร้างโฟลเดอร์ในโปรเจกต์
```
/freeworld
  /src
    /world       -> โค้ดเกี่ยวกับแผนที่ ทรัพยากร
    /characters  -> โค้ดตัวละครและ Utility AI
    /building    -> ระบบสร้างสิ่งของ
    /social      -> ระบบสังคม (เฟส 4)
    /storage     -> โค้ดเชื่อม Google Drive
  /docs          -> เอกสารประกอบ (รวมไฟล์นี้)
  README.md
```

### 5.2 รูปแบบข้อความ commit
```
[เฟส-N] คำอธิบายสั้นๆ ว่าทำอะไร
```
ตัวอย่าง: `[เฟส-2] เพิ่มระบบคำนวณค่าความหิวและพฤติกรรมหาอาหาร`

### 5.3 การตั้งชื่อ
- ชื่อไฟล์/ฟังก์ชัน: ภาษาอังกฤษ, `camelCase` สำหรับ JS, `kebab-case` สำหรับชื่อไฟล์
- คอมเมนต์ในโค้ด: ภาษาไทยได้ เพื่อให้อ่านง่ายตอนกลับมาแก้

---

## 6. มาตรฐานการเชื่อมต่อ Google Drive

- อ่าน credential จาก environment variable ชื่อ `GOOGLE_DRIVE_CREDENTIALS` เท่านั้น ห้าม hardcode
- โครงสร้างโฟลเดอร์บน Drive:
```
/freeworld-ecosystem
  /snapshots        -> สถานะโลกทั้งหมด บันทึกทุกจบ 1 ปีในเกม
  /logs             -> เหตุการณ์สำคัญ (ตัวละครตาย, สร้างสิ่งของใหม่ ฯลฯ)
```
- ชื่อไฟล์: `snapshot_YYYY-MM-DD_HHmm.json`
- ทุกไฟล์ต้องมี field `timestamp`, `gameYear`, `worldState`, `characterCount` เป็นอย่างน้อย
